# User Dictionary

The EDICT user dictionary is an editable local resource, normally `user.dct` beside `dict.cfg` unless its registry entry names an absolute path. It is separate from **Tools > User Conversions**, which manages WNN readings and conversion candidates rather than dictionary definitions. A missing user dictionary is acceptable until the first saved entry. User entries participate in configured lookup and are displayed in the highlight color to distinguish their provenance.

Open it from **User Dictionary** in lookup or the dictionary settings. JWPqt uses one application-owned, modeless working-copy editor. It can stay open after Dictionary Search closes, and the manager will not replace resources while its editor is open because that would discard its working copy. Changes are not live until **Save** publishes a complete dictionary through the atomic file boundary. **Cancel** intentionally discards the working copy without another prompt.

The entry list supports the original keyboard actions as well as buttons: Insert adds, Space edits, Delete removes, and Ctrl+Up/Ctrl+Down changes order. Ctrl+C or Ctrl+Insert copies the current displayed row without changing or saving the working copy. **Sort** orders the user entries by the recovered kana-based display order. `Ctrl+I` opens Character Information for the first original JIS headword character, falling back to the reading; `Ctrl+L` or F5 opens Radical Lookup with it when it has a JIS X 0208 mapping. `F23` opens the row context menu and `Ctrl+F4` follows the normal close prompt.

**Import** accepts several local files at once, and files may be dropped on the editor. Every chosen file is parsed in source order before the working copy changes; a missing, malformed, or oversized file leaves no partial import. Import starts in the configured user-file directory. Imported legacy-compatible records are retained rather than silently rewritten to satisfy the stricter Add/Edit validator. Saving remains explicit.

Closing a modified editor through its title bar asks whether to save, with Yes as the safe default. Yes performs the same atomic Save; an error keeps the window and its data open. No closes without publishing. On application exit, user dictionary and conversion working copies are checked before documents or settings; a discarded close attempt remains dirty if a later exit prompt is cancelled. Use [Adding or Editing Entries](help:IDH_DICT_USEREDIT) for field rules and [Dictionaries](help:IDH_DICT_DICTIONARIES) for its resource definition.

# File Types

JWPqt 2.00 works with structured Japanese documents and plain-text documents. A Normal JWPce document normally uses `.jce`; a JWP document normally uses `.jwp`. In this release those two choices use the same native structured JWP codec. A new Japanese document defaults to `.jce`, while an existing `.jwp` document keeps that extension when saved. Native JWP retains paragraph formatting, hard page breaks, page-layout metadata, document summary data, and headers and footers. These are the formats to choose when those document-level features must survive. See [What is saved with a JWPce File?](help:IDH_FILE_CONTENTS) and [The Page Layout Dialog Box](help:IDH_PRINT_LAYOUT).

Supported text formats are UTF-8, UTF-7, UTF-16 little-endian and big-endian, JFC, EUC-JP, Shift-JIS, and New-, Old-, and NEC-JIS. The editor records the chosen encoding with the document. BOM-marked Unicode is detected; UTF-16 without a BOM requires an explicit filter or encoding choice. Unmarked ambiguous content is not silently guessed: choose its encoding. UTF-16 preserves the input byte order and BOM, supports supplementary Unicode, and rejects malformed surrogate pairs. Switching a document to UTF-16 writes a BOM so it can subsequently be detected. See [Opening an Existing File](help:IDH_FILE_OPEN) and [Japanese Encoding Systems](help:IDH_FILE_ENCODING).

JFC is plain text rather than a structured JWP container. It opens as UTF-8 first, with strict compatibility fallback for the recovered old EUC form, and always saves as UTF-8 without a BOM. A `.jfc` extension, its file-dialog filter, or an explicit JFC encoding selects that policy. JWPqt validates output before changing a destination; unsupported or malformed data is an error, not replacement characters. Save As can move between formats after validation and any required loss confirmation. Export Copy produces another representation without changing the current document's path, clean baseline, modified state, or undo history. See [Saving Files](help:IDH_FILE_SAVE) and [JFC Files](help:IDH_FILE_JFC).

The Web build has a different file boundary. Open uploads one local file, and Save downloads the encoded result after updating the browser-owned working copy. It cannot offer arbitrary local paths or a referenced-files workspace. Browser projects and printing are unavailable; native desktop formats and workflows described here apply on Linux, Windows, and macOS.

# Choosing a Japanese Display Font

Choose Japanese screen roles in **Tools > Options > Fonts** according to where content is displayed: System, Edit, List, KanjiBar, File, Big, Table, and Bitmap. Automatic inheritance lets a child role receive the parent family and size. When a selected family cannot be loaded, the child inherits its parent role while JWPqt keeps the unavailable requested name and emits a diagnostic. This retains explicit configuration without pretending the missing family was successfully applied.

System, Edit, List, KanjiBar, File, Big, Table, and Bitmap are content roles, not desktop menu fonts. Table always uses 16 logical pixels, and Big expands to fit its available pane. File controls document display. Hold Ctrl while scrolling over the active document to adjust File by one logical pixel per wheel notch in the range 1 through 1024. The first adjustment turns an inherited File role into an explicit setting at its currently rendered size. All open documents update, while ordinary scrolling, query/list fonts, text, selection, Undo, and modified state are unchanged.

Selectors normally list families advertising Japanese support. Enable Show all installed families when a usable installed font is not correctly advertised. The checkbox does not alter the current selection, a manually entered family, or a `.f00` path until Options is accepted. Selecting an arbitrary font that lacks required glyphs is not treated as proof that it provides Japanese rendering; fallback is reported rather than silently changing the role hierarchy.

Legacy `.f00` entries remain available for screen roles. Relative filenames resolve from the settings directory; absolute paths are accepted. The native renderer decodes supported packed or holey JIS bitmap tables into a private face at the bitmap's original screen height. This preserves original raster source data without installing the file system-wide. Native applications do not silently treat legacy bitmap files as already-loaded Qt fonts: an unavailable or invalid file yields diagnostic fallback.

Display size and Print size are intentionally different concerns. Screen roles use logical pixels for readable native presentation; Print uses physical points and page settings. If copied text needs a bitmap representation, the Bitmap role inherits File when Automatic, and its vertical mode uses its own role settings. See [Font/Format Options](help:IDH_OPTIONS_FONT), [File/Clipboard Options](help:IDH_OPTIONS_FILECLIPBOARD), and [Choosing a Japanese Printer Font](help:IDH_FONTS_PRINTER).

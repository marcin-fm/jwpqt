# Page Breaks and Formatting

JWPqt retains structural hard page breaks in native JWP documents. Ctrl+Enter inserts one as a single undoable document command after pending input/conversion is resolved. The rich editor shows hard page breaks in its continuous layout, and the native paged renderer carries them into printing and preview. Paragraph formatting, including indents, proportional spacing, and hanging indents, also participates in the physical-point pagination. See [Printing](help:IDH_PRINT_GENERAL) and [Actually Printing Something](help:IDH_PRINT_PRINTING).

Normal pagination is computed by the print renderer rather than represented as a permanent text edit. A hard page break is different: it is document structure and is preserved by the native JWP model. Page Layout changes and Printer Setup can affect the current document's margins/orientation; accepted printer-setup changes are one undoable change to that original document. Existing JWP files retain saved layout, while default page settings initialize new Japanese documents and imported text. See [The Page Layout Dialog Box](help:IDH_PRINT_LAYOUT) and [Margins, Vertical Printing, and Paper Orientation](help:IDH_PRINT_MARGINS).

PDF output supports exact selections and page ranges. Selection/range output omits unwanted text from the PDF stream rather than covering it with clipping. Output reformatting is frozen when Print or Preview begins, so later edits cannot move page breaks under the job. Invalid geometry, ranges, or output bounds fail before an existing PDF is replaced. See [Actually Printing Something](help:IDH_PRINT_PRINTING) and [Temporary Files and System Failures](help:IDH_FILE_TEMP).

Saving a JWP document preserves hard page breaks. Saving or exporting as text can lose them along with paragraph/page layout, headers, footers, and summary metadata, and JWPqt asks for confirmation where such loss applies. That explicit boundary is preferable to silently converting a document's pagination into ordinary newline characters. The Web port can edit and save/download encoded content but has no native Print or Preview workflow, so paged output inspection belongs on the native desktop port.

# Adding or Editing Entries

Choose **Add** or **Edit** in the User Dictionary window to edit one dictionary record. The dialog has separate reading, headword, and meaning fields, each using the local K/A/J input control. They use the application window's current Insert/Overwrite mode. Pending romaji is completed before validation; a rejected value leaves the editor open with every field intact so that it can be corrected.

The reading is required, may not contain spaces, and is normally kana. Existing compatible data can contain a non-kana reading, but Add and Edit explicitly ask for confirmation in that case and default to **No**. A headword is optional: leave it empty when the entry has no kanji form. When it does have a kanji spelling, include its okurigana in the headword rather than treating the kana suffix as unrelated data. Selection from a document or lookup can reduce retyping, but review which field receives it.

The meaning is an English definition string. Separate multiple meanings with `/`, consistent with EDICT-style records. Put applicable dictionary codes such as `(n)`, `(adj-na)`, `(vs)`, `(vi)`, `(vt)`, `(pref)`, or `(suf)` in parentheses in the definition, using comma-separated codes within a group. See [Dictionary Codes](help:IDH_DICT_CODES). Do not treat the user dictionary as a place to reproduce copyrighted reference text without permission.

For entries intended for a cooperative EDICT-style contribution, use a plain verb form whose first English wording begins `to `, and supply `vi` or `vt` when it is not otherwise clear. Use noun tags such as `an`, `a-no`, or `vs` where appropriate rather than entering `na`, `no`, or `suru` into the Japanese headword. Mark prefixes and suffixes with `(pref)` or `(suf)`, not a hyphen in the Japanese. Avoid unnecessary articles, guessed kanji, and `/`, `[` or `]` inside data that would conflict with record syntax. Check kana carefully, including long-vowel and `zu` ambiguities, and avoid predictable suffix formations unless they are genuinely lexical.

These conventions help interoperability, but JWPqt validates editor safety rather than claiming every imported legacy entry conforms. The saved result is a local user resource, not an automatic upstream submission. Use [User Dictionary](help:IDH_DICT_USERDICT) for import, ordering, and save behavior; use [Adding or Editing Dictionaries](help:IDH_DICT_ADDDICT) if the user file path itself must change.

# Working with kanjinfo.dat

Kanji lookup uses external data deliberately and visibly. `kanjinfo.dat` provides the kanji metadata used by Bushu, SKIP, Spahn-Hadamitzky, Four Corner, Reading, and Index searches. The recovered radical and stroke catalog files supply the graphical radical and stroke workflows. Normal packages discover the matching resource set; an explicit configuration resource set takes precedence as a whole. Do not replace one member of a matching set and expect JWPqt to merge it with packaged files: incomplete or malformed overrides fail rather than producing uncertain results.

The practical result is that availability follows the data you installed. A full data set permits the largest available reference list, extended metadata, and supplementary readings. Smaller or data-free installations still let JWPqt inspect printable Unicode characters and JIS mappings, but they cannot promise every lookup or reference. JWPqt distinguishes that condition from a no-match search: a missing resource, corrupt metadata record, disabled SKIP miscoding option, or unavailable saved Index/Reading type is reported in the interface. It does not present zero, blank, or a different index as if it were the requested value.

For frequent lookup use, rely on the native resource loader rather than a legacy memory-cache setting. JWPqt loads and validates its native external resources, and its lookup dialogs preserve their pending criteria and result strips when Options are applied. There is no documented user control that recreates the old `Cache Kanji Information` checkbox. Automatic lookup is a separate usability preference: it schedules a search after a criterion changes; disabling it keeps the query pending until **Search**.

The current code treats corrupt metadata defensively. Invalid headers, truncation, invalid string data, broken variable offsets, and exhausted limits are errors. Character Information falls back to basic codes when it cannot read a record. Lookup pages requiring the data report failure instead of returning invented candidates. This distinction matters when copying a result into a document or using it as evidence for an index: verify the status line before acting on a partial resource installation.

Runtime Resources and the Options dialog disclose resource and retained-setting conditions. JWPqt saves preferences through native configuration and JPR workspaces, but a preference that refers to unavailable metadata is kept with an explicit fallback. See [Alternate kanjinfo.dat Files](help:IDH_KANJI_KANJINFO) for data scope, [Finding Kanji](help:IDH_KANJI_LOOKUP) for shared behavior, and [Character Information](help:IDH_KANJI_CHARINFO) for data-free character inspection.

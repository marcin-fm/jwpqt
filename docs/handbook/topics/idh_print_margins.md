# Margins, Vertical Printing, and Paper Orientation

Margins and orientation define the printable body area for the current native JWP document. The native renderer paginates in physical points, preserving paragraph indents, spacing, hanging indents, and structural hard page breaks inside that area. Measurements can be displayed in inches or centimeters through Options > Default Page; switching the display unit converts the dialog values but does not round or rewrite stored margins merely because units changed. JWP documents and saved defaults continue to store margins in inches. See [The Page Layout Dialog Box](help:IDH_PRINT_LAYOUT) and [Page Breaks and Formatting](help:IDH_PRINT_PAGEBREAK).

Default Page supplies margins and orientation for new Japanese documents and newly imported text. Existing JWP documents preserve their own stored layout. From Default copies defaults into the active document; Set as Default stages active margins/orientation as defaults for later documents. Cancel preserves both existing document state and preferences. Accepted document layout changes are undoable, but undo does not reverse the application default change. See [The Page Layout Dialog Box](help:IDH_PRINT_LAYOUT).

Vertical JWP output follows the recovered physical-paper convention: read the sheet after turning it clockwise. Japanese glyphs are counter-rotated according to the vertical rules, while Latin text remains upright. TrueType vertical alternates affect Japanese punctuation and letters; raster fonts retain their source exception and ink-position rules. This is not a new top-to-bottom document model and does not promise pixel-identical historical Win32 rounding or placement. See [Printing Options and Fonts](help:IDH_PRINT_OPTIONS).

The renderer also allows one eligible closing-punctuation or small-kana cell to extend into the physical right margin when the configured margin-relaxation rule applies. Invalid page geometry fails safely before PDF publication. Printer Setup can initialize physical margins/orientation and, once accepted, applies the result only to the original document as one undoable change. On the Web port, no native Print or Preview workflow exists, so these settings must not be presented as browser printing capabilities.

# Color-Kanji Options

Open **Tools > Kanji Color Options** to control the display policy that uses the external Kanji Color List. JWPqt validates and saves all policy components together before it publishes changed colors, so a failed settings write restores the prior policy and overlays. The policy is independent from membership management; use [Creating and Clearing a Kanji List](help:IDH_KANJI_KANJILIST) to make, append, edit, view, or clear the list.

Set **List mode** to Off, Members, or Nonmembers. Off disables list-based coloring. Members colors characters that are present in the supported color list. Nonmembers colors supported kanji that are not present. Set the list color separately. A listed character is recognized only within the list's valid recovered JIS range; no arbitrary Unicode character becomes a member just because its glyph resembles a kanji.

Enable or disable **uncommon kanji** coloring and select its color. JWPqt regards the native JIS uncommon range as uncommon for this purpose. List coloring takes precedence over uncommon coloring. For example, in Members mode a listed uncommon kanji receives the list color; an unlisted uncommon kanji can receive the uncommon color if that option is enabled. In Nonmembers mode an eligible unlisted character receives the list color before the uncommon rule is considered. This provides a predictable way to distinguish a study list from a general Level II warning color.

The rendered color is an editor overlay. It preserves document content, undo history, selection, conversion preview handling, and modified state. It refreshes after changes that alter JWP presentation; it is cleared for plain text documents. The current appearance follows the native palette, while the policy's RGB values are persisted in a strict validated record. A corrupt policy is rejected as a whole instead of mixing new and old fields.

List operations and color-policy changes remain inert during an active WNN conversion, preserving conversion state. The policy can persist across settings, restart, and supported JPR workspace state, but it cannot make missing external list data valid. For a membership audit, use **Count Kanji** with All, Exclude color list, or Only color list. See [Color Kanji](help:IDH_KANJI_COLORKANJI), [Creating and Clearing a Kanji List](help:IDH_KANJI_KANJILIST), and [Count Kanji](help:IDH_KANJI_COUNTKANJI).

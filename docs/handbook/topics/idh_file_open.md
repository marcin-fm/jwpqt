# Opening an Existing File

File > Open opens documents through the selected or detected format policy. The native application supports structured `.jce`/`.jwp` documents, UTF-8, UTF-7, UTF-16LE/BE, JFC, EUC-JP, Shift-JIS, and New-, Old-, and NEC-JIS text. The explicit encoding choice is important for ambiguous or unmarked data. BOM-marked UTF-16 can be detected, while unmarked UTF-16 requires an explicit filter. UTF-7 also needs an explicit choice where ASCII content cannot safely reveal the intended encoding. Unsupported byte sequences and unsupported output characters fail visibly rather than being silently replaced. See [Japanese Encoding Systems](help:IDH_FILE_ENCODING) and [File Types](help:IDH_FILE_TYPES).

Interactive Open can offer a limited recovery path for a damaged structured JWP document only after the header and metadata validate. The warning defaults to No and reports retained complete paragraphs, any retained partial paragraph, and ignored trailing bytes. If accepted, the recovered document opens modified; use Save As if the damaged source must remain untouched. Invalid headers or metadata, malformed undo data, truncation outside the recognized recovery case, and safety-limit failures remain fatal. Automated opens, project loading, and Revert do not use this recovery path. See [Common Difficulties Opening Files](help:IDH_FILE_PROBLEMS) and [Opening the Same File Again](help:IDH_FILE_REVERT).

You may drop one or more local files on the native main window. They are processed in source order through the same detection, project, and duplicate-file rules as menu Open. An unreadable item reports its own error without preventing later dropped files from opening. Directories and nonlocal URLs are not accepted. Command-line arguments behave similarly: repeated paths activate an existing tab, and an unreadable argument does not prevent later arguments from opening. If all supplied paths fail in noninteractive startup, the application returns failure. See [Duplicate Files](help:IDH_FILE_DUPLICATE) and [Working with Projects](help:IDH_FILE_PROJECT).

In a Web browser, Open invokes a browser file picker and stages one uploaded file in persistent browser storage before bounded detection. It is not access to an arbitrary local path. The browser upload limit is 64 MiB, and JPR project open is disabled because browser uploads cannot retain stable references to all workspace files.

# General Options

General Options controls application-wide behavior rather than the text or page layout of one document. The window-close policy can either close the current file or close the application. Explicit Quit always exits the application after its normal save checks; modifier close commands also distinguish application and file closure. The confirmation for closing the final file can be disabled, but modified documents and failed persistence still require an exit decision. These choices persist through settings and projects.

Native defaults are: restore window/maximize window/close-button-closes-file/startup dictionary/reload previous files/keep-backup-copy off; confirm-last-file-exit, save settings/recent files/histories, revert-to-Kanji, and result insertion on; and metric units, old katakana handling, and Ctrl+Up/Down conversion off. Opening an already-open file defaults to Ask each time; the other choices are Change to the open document and Open another copy. Window geometry is native logical pixels: positions are -1,000,000 through 1,000,000, sizes are 0 through 32,768, and zero dimensions request platform defaults.

**Restore main window** saves normal window bounds and maximized state, never minimized geometry. The restored placement is bounded and clamped to the screens available on the current native desktop. JWPqt also remembers placement independently for six source dialog roles; importing settings does not move already-open windows. This is intentionally a desktop-native restoration mechanism, not an attempt to reproduce a Win32 monitor record exactly.

**Restore named files from the previous session** is opt-in. When enabled, startup reads the application-scoped `last-session.jpr` before command-line files. It preserves named-file formats and active-tab order while retaining current preferences. Missing or invalid references are reported without preventing other usable files from opening. Unnamed buffers and unsaved text are never serialized. If saving the session archive fails because it is corrupt, locked, or externally changed, JWPqt does not overwrite it; exit can be cancelled or continued without saving.

The line-width policy applies to JWP documents. Choose dynamic width to follow the editor window, a fixed width of 5 through 1000 full-width characters, or printer width to match the current printable page and physical print font. Printer width responds to orientation, margins, font, and Page Layout changes. Changing it only reformats the view: text, paragraph metadata, saved state, and Undo history remain unchanged. Imported text stays window-wrapped even if Japanese editing is available.

Dynamic width is the default and the fixed-width value defaults to 35 characters. The default page measurements are configured separately under Default Page; changing metric display changes units, not stored dimensions.

Related controls include recent-file and query-history persistence, the default JWP code page, dictionary search policies, and startup dictionary behavior. These settings belong to the application profile, while file-specific layout is not silently folded into them. For saved preference mechanics, see [Introduction](help:IDH_OPTIONS_INTRO); for visible chrome and theme behavior, see [Display Options](help:IDH_OPTIONS_DISPLAY). The old Windows CE page-scroll controls were device-specific behavior and are not presented as native JWPqt 2.02 options.

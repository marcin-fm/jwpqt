# Headers and Footers (Page Numbering)

JWP documents support headers and footers as native page-layout metadata. They can have separate fields for odd and even pages and can suppress headers/footers on the first page. The fields are placed around the printed page using the layout offsets described in [Advanced Layout Options](help:IDH_PRINT_ADVANCED). The document's header/footer text uses the same K/A/J input controls and Insert/Overwrite policy as ordinary editing; pending kana is completed before Page Layout validates and applies it. See [The Page Layout Dialog Box](help:IDH_PRINT_LAYOUT).

Headers and footers are produced by the paged native renderer, not copied from a scrolling on-screen display. A print/preview job freezes document metadata and its formatting before the output dialog opens, so later edits to the header/footer fields do not affect the existing job. Header/footer output must fit the paper; invalid geometry fails before replacing a pre-existing PDF. Preview uses the same snapshot and layout rules as Print. See [Actually Printing Something](help:IDH_PRINT_PRINTING).

Use substitution codes to insert values such as document Title, Subject, Author, Keywords, Comment, full path, base filename, date, time, page number, or a literal ampersand. The detailed code list is in [The Header and Footer Strings](help:IDH_PRINT_HEADSTRINGS). The document summary supplies the Title, Subject, Author, Keywords, and Comment values, while Date/Time output follows the global configured patterns captured once per job. See [Document Summary](help:IDH_PRINT_SUMMARY) and [Date and Time](help:IDH_PRINT_DATETIME).

Native JWP preserves header/footer metadata. Text export may lose it and requires the applicable confirmation rather than silently flattening it. The Web build cannot Print or Preview because Qt WebAssembly lacks PrintSupport. It also cannot use JPR referenced-file workspaces, so browser persistence of uploads/settings is not a replacement for a native header/footer printing workflow.

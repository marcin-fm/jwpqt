# What is saved with a JWPce File?

For JWPqt 2.01, a native JWP document is the format that carries more than visible characters. Normal JWPce (`.jce`) and JWP (`.jwp`) use the structured JWP representation, preserving paragraph formatting, hard page breaks, document summary metadata, and headers and footers. The current file's page layout is part of that native document state. That distinction matters when selecting Save As: text formats retain text and their encoding, but cannot retain the native paragraph and page-layout information. The application asks for confirmation when exporting text would lose paragraph/page layout, header/footer data, summary metadata, or hard page breaks. See [File Types](help:IDH_FILE_TYPES) and [Saving Files](help:IDH_FILE_SAVE).

Page Layout applies margins and orientation to the current document. Existing JWP files keep their stored layout. Headers and footers can have distinct odd and even fields and suppress the first page; they can refer to the document Title, Subject, Author, Keywords, and Comment fields. The summary fields are also native metadata. Default margins and orientation are application defaults for new Japanese documents and imported text, not a mechanism for retroactively changing saved JWP files. See [Margins, Vertical Printing, and Paper Orientation](help:IDH_PRINT_MARGINS), [Headers and Footers (Page Numbering)](help:IDH_PRINT_HEADERS), and [Document Summary](help:IDH_PRINT_SUMMARY).

The structured format also preserves the native document's Japanese editing and formatting model rather than flattening it into a text stream. A JWP save has explicit compatibility boundaries: the port opens and saves recovered JWP B1, B2, and J1.20 documents and omits embedded undo data on native saves. Valid packed JWPxp x86 undo payloads are skipped when loading, as in the source loader; native undo history is not restored from that payload. Damaged documents do not gain hidden repair semantics merely by being native. Interactive Open can offer limited recovery only after header and metadata validation, while Revert and project restoration remain strict. See [Common Difficulties Opening Files](help:IDH_FILE_PROBLEMS) and [Opening the Same File Again](help:IDH_FILE_REVERT).

Use Export Copy for a derivative representation that must not alter the working document. It cannot overwrite the source itself or a path that belongs to another open document. Use Save As when the live document is intentionally changing name or format; that operation establishes the chosen representation as the document's saved format after success.

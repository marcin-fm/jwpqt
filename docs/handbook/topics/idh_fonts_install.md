# Installing Additional Fonts

JWPqt uses the host platform's public installed font families and can also load an explicitly selected legacy `.f00` bitmap file as a private application face. It does not install, copy, modify, or redistribute a font merely because it is selected in Options. This differs from the historical Windows-focused installation instructions: native desktop menu fonts remain under the platform's control, and the WebAssembly build embeds its supplied Noto Sans JP asset because a browser cannot use arbitrary host fonts.

For a system font, install it using the normal mechanism of Linux, Windows, or macOS, then select it in **Tools > Options**. Japanese and printer selectors normally list families that advertise Japanese support. Enable **Show all installed families** to inspect all public families when a known-capable font is not advertised correctly; accepting the Options dialog is required to change a selection. The ASCII selector always presents the complete available family list. If a chosen family is unavailable at runtime, JWPqt retains its original name, inherits the parent role's available face and size, and reports a diagnostic.

For a legacy bitmap, type a `.f00` filename in the relevant role. Relative paths resolve from JWPqt's settings directory, not a guessed Windows program directory; absolute paths are accepted. The native decoder accepts the recovered packed or holey JIS layouts and safely handles supported alignment forms. Loading has explicit limits: up to 8 MiB per source, 64 MiB per generated face, and 64 MiB across at most 16 application-cache faces. Invalid or unavailable screen fonts fall back by role inheritance. An invalid explicit Print font fails before output is written, protecting the destination from a partial print result.

Private generated faces are not persistent public font names. The source bitmap stays unchanged and is not installed globally or included in an application package. Its original license remains binding, and generated faces restrict font embedding. Closing JWPqt releases the private cache. The normal package itself has separate data and font obligations: it includes original lookup payload notices where configured, and the Web build includes the embedded Noto Sans JP OFL.

Old JWPce documentation described copying `.f00` files beside the executable and working around Windows CE TrueType detection. That is historical migration information, not a native installation prescription. Use [Font/Format Options](help:IDH_OPTIONS_FONT) to assign roles and [Support](help:IDH_SUPPORT_GENERAL) for packaging and license diagnostics.

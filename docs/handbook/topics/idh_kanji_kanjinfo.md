# Alternate kanjinfo.dat Files

`kanjinfo.dat` is external kanji metadata, not a built-in substitute dictionary. In a normal JWPqt package it is supplied unchanged with the recovered JWPce/JWPxp lookup data, alongside `radical.dat`, `stroke.dat`, and `radicals.bmp`. JWPqt discovers those packaged files automatically. A configuration directory containing `dict.cfg` or any explicit kanji resource overrides that packaged set. An incomplete or malformed override fails visibly; JWPqt does not silently combine unrelated partial datasets.

The installed metadata determines what Character Information can show and which data-driven lookup choices are available. Basic records provide character associations such as Bushu, strokes, grade, primary dictionary indexes, and normal readings. Extended records can add Spahn-Hadamitzky, Four Corner, Morohashi, cross-references, extra dictionary indexes, pinyin, Korean, and nanori. Consequently, a control, reading type, or index may be absent from a particular data set. JWPqt retains a saved unavailable default but presents a visible fallback rather than pretending that the unavailable data can be searched.

This is especially important for Reading and Index Lookup. Nanori, pinyin, and Korean types appear only when the loaded metadata advertises them. Index Lookup presents its available leading reference types when data lacks the extended index portion. The SKIP **Include miscodes** option is disabled when the data has no SKIP cross-references, although its saved preference is retained. Character Information reports metadata failures and continues with basic character codes; it never manufactures a dictionary number or reading.

A data-free GPL-only build is supported. It contains no bundled noncommercial legacy lookup payload. In that configuration, or when external metadata is deliberately omitted, character inspection still supports Unicode and JWP character-code information, and the JIS table remains useful. Searches that require the missing data either have no available control or report the resource limitation. Graphical radical and stroke catalog behavior depends on its corresponding external data, so use the Runtime Resources status and the visible diagnostic rather than assuming all lookup modes are present.

Replacement data must be compatible with the original external format and licensing conditions. JWPqt validates headers, record bounds, strings, and reference budgets while loading it; damaged data is rejected rather than partially trusted. Changing data changes the available factual metadata, not JWPqt's documented commands. See [Character Information](help:IDH_KANJI_CHARINFO), [Working with kanjinfo.dat](help:IDH_KANJI_KANJINFODAT), [Reading Lookup](help:IDH_KANJI_READLOOKUP), and [Index Lookup](help:IDH_KANJI_INDEXLOOKUP).

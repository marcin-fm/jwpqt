# File/Clipboard Options

<!-- metadata: legacy JWPce.cnt reused IDH_OPTIONS_FONT for this topic; JWPqt assigns the canonical IDH_OPTIONS_FILECLIPBOARD. -->

File/Clipboard Options covers duplicate-file behavior, backups, list insertion, and exchange formats. Opening a path already open activates its existing tab rather than creating a hidden duplicate. Save As and Export Copy cannot overwrite another open document's path. **Keep the previous disk version** enables source-compatible `_BAK` backups, off by default. Before a successful overwrite, JWPqt copies the exact prior bytes to an appended name such as `notes.jwp_BAK`, then atomically publishes the new document. New files do not remove an existing backup; invalid encoding, protected destinations, open documents, and failed backup creation leave the document and old backup intact.

The native clipboard supports EUC-JP, Shift-JIS, new/old/NEC JIS, Unicode, UTF-7, and UTF-8. Automatic import first prefers a private JWP fragment, then its exact encoded-text representation, then declared external text and ordinary Unicode. The fragment retains structured paragraphs and original JIS-versus-code-page identity. Invalid or unrepresentable input never partly changes a document, and a multi-paragraph paste is one Undo operation.

Fresh settings use Unicode import, a separately encoded Shift-JIS export, standard Unicode publication, omitted bitmap output, vertical bitmap mode off, bitmap list coloring off, and Automatic translation code page, which resolves to native CP1252 on Linux. Explicit translation-code-page choices are CP1250 through CP1258. Choose Auto Detect when external encoded representations should be examined before ordinary Unicode. **Omit Unicode** also suppresses rich text so it cannot leak an unrequested Unicode copy, while retaining native and configured encoded data. Linux MIME types replace legacy Windows clipboard IDs; standard `text/plain;charset=...` providers can exchange the configured encoding.

Bitmap is the image role for copied document text and inherits File when Automatic. Omit bitmap removes only the image, not text or rich formats. Images have white paper and are bounded to 262,144 selected UTF-16 positions, 8,192 pixels per edge, and 16 million pixels. An oversized image is omitted with a status message while text still copies. Vertical bitmap mode uses its own font settings: Japanese glyphs are counter-rotated for reading after a clockwise paper turn; Latin and source raster punctuation exceptions remain horizontal. It does not rotate the entire image. Color clipboard mode uses persistent kanji colors only with active list coloring, never selection or conversion highlights.

**Insert complete result-list entries on separate lines** starts enabled. Dictionary, accumulated-result, count, and user-dictionary rows then become separate paragraphs. Disable it to join rows compactly using a tab at eligible ASCII boundaries or direct joining at Japanese/already-spaced boundaries. See [Font/Format Options](help:IDH_OPTIONS_FONT) and [Choosing a Japanese Display Font](help:IDH_FONTS_DISPLAY).

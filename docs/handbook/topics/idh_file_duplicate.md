# Duplicate Files

Opening a pathname that is already represented by a tab deserves an explicit choice because two independently edited copies can overwrite each other. JWPqt's Display And Files settings can ask whether to use the existing open document, reload it, or open an independent copy. The settings can also automatically choose either non-destructive action. Using the existing document activates its tab. Reloading uses the existing tab and its established file format. Opening an independent copy intentionally creates another tab and is appropriate only when you understand that its edits and saved baseline are separate. See [Changing the Current File](help:IDH_FILE_CHANGE) and [Opening the Same File Again](help:IDH_FILE_REVERT).

The safe routine is normally to activate the open tab. An independent copy is not synchronized with the original tab; saving both to the same pathname can make the later save win. Reloading replaces the current in-memory content from the source and therefore is for deliberately discarding/replacing it, not for merging changes. If the open tab is modified, the normal save/discard/cancel protections apply before an action can discard its work. See [Closing Files](help:IDH_FILE_CLOSE) and [Saving Files](help:IDH_FILE_SAVE).

Not every opening path presents a duplicate dialog. Scripts and replacement-oriented APIs deterministically use the existing tab. Command-line startup activates a repeated path rather than creating a hidden duplicate. File > Recent Files records the encoding or JWP code-page choice for each entry, so reopening can use the remembered representation rather than guessing its encoding again. Recent reopening likewise activates an existing tab or opens a new one according to the available document state. See [Opening an Existing File](help:IDH_FILE_OPEN).

Save As and Export Copy have an additional guard: neither can overwrite a pathname currently open in another document. This prevents a format conversion or derivative export from silently changing another tab's source. The Web build shares the logical tab behavior for its staged uploads, but browser files do not provide the stable desktop paths needed for a JPR referenced-files workspace.

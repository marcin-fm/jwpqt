# Common Difficulties Opening Files

The most important opening problem is uncertainty about the source representation. JWPqt does not treat a readable-looking result as proof that a byte stream was correctly identified. UTF-16 with a byte-order mark is detected and preserves its byte order; unmarked UTF-16 needs its explicit encoding choice. UTF-7 is deliberately not auto-identified from the shared ASCII-looking `.utf` space, so select UTF-7 when it is known to be the source format. For other ambiguous unmarked input, choose the intended filter rather than relying on a silent guess. See [Japanese Encoding Systems](help:IDH_FILE_ENCODING) and [Opening an Existing File](help:IDH_FILE_OPEN).

The port's generic EUC-JP and Shift-JIS codecs are strict. They reject malformed sequences, unassigned mapping cells, JIS X 0201 halfwidth kana, JIS X 0212, vendor extensions, and Unicode outside the recovered repertoire. This prevents apparently successful imports from silently substituting data. New-, Old-, and NEC-JIS are also separate choices. JFC follows its own policy: it tries strict UTF-8 first, then the recovered old-EUC compatibility form, and it saves UTF-8 without a BOM. See [JFC Files](help:IDH_FILE_JFC).

A damaged structured JWP file is a different problem from an uncertain text encoding. Interactive Open can offer recovery only when its header and metadata validate and a damaged paragraph stream has a readable prefix. The prompt defaults to No, describes what is retained, and marks accepted recovery modified. It never rewrites the damaged source until an explicit save. Invalid headers, malformed metadata, malformed or truncated unrecognized payloads, and limit failures are fatal. Project staging, automated open, and Revert remain strict specifically so they cannot silently replace a workspace or a source baseline with partial data. See [Opening the Same File Again](help:IDH_FILE_REVERT) and [Working with Projects](help:IDH_FILE_PROJECT).

If a destination cannot encode the document, Save As fails before changing it. If a recent-history record is corrupt, it is preserved until explicitly cleared and its problem appears in Runtime Resources rather than becoming a document-I/O failure. Browser uploads receive the same bounded format detection, but upload size is limited and browser file access cannot resolve desktop paths.

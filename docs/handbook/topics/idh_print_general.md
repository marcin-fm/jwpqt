# Printing

JWPqt's native desktop printing renders a frozen snapshot of the document text, formatting, selection, metadata, and font choices. File > Print and Print Preview create that snapshot before their dialogs open, so later edits or tab changes cannot substitute another document into the job. The native renderer paginates in physical points and preserves paragraph indents, spacing, hanging indents, and hard page breaks. It supports horizontal and the recovered physical-paper vertical convention. See [Actually Printing Something](help:IDH_PRINT_PRINTING), [Page Breaks and Formatting](help:IDH_PRINT_PAGEBREAK), and [Margins, Vertical Printing, and Paper Orientation](help:IDH_PRINT_MARGINS).

On native Linux, Windows, and macOS builds, output can go through the system print workflow or to PDF. The port's accepted verification workflow is PDF text, image/geometry, pagination, range, and cancellation testing; physical-printer hardware is not an acceptance gate. This does not claim that every printer backend or legacy Win32 raster placement has been tested. Native spool errors are reported, and cancellation cannot recall pages already sent to a physical printer. See [Actually Printing Something](help:IDH_PRINT_PRINTING).

The Web build is an explicit boundary, not a degraded printer dialog. Qt WebAssembly has no PrintSupport, so browser printing and Print Preview are unavailable. Browser Open uploads one local document and Save downloads the encoded result; browser-owned copies/preferences and optional named-session references persist in IndexedDB. JPR workspaces are also unavailable because uploads cannot give stable access to all referenced files. Do not describe native print commands as available inside the browser. See [Opening an Existing File](help:IDH_FILE_OPEN) and [Working with Projects](help:IDH_FILE_PROJECT).

Screen appearance is not a complete page-layout proof. The desktop editor is continuously scrolling, while the native print renderer performs paged layout. Preview is the appropriate way to inspect the frozen output snapshot before printing, including its headers, margins, page breaks, font choices, and page count. It does not itself publish to the remembered PDF destination.

# Printing Options and Fonts

JWPqt separates native printing font configuration from screen-font dimensions. Options > Printing stores `Print.Font`, `Print.Size`, and `Print.Auto` in settings and projects. The print size is physical points in the dialog and tenths of a point on disk, not display pixels. With automatic selection, output uses the document font family. With an explicit family, Qt's native font fallback applies. The application captures the selected font policy for a Print or Preview job, so later option changes cannot alter that job. See [Actually Printing Something](help:IDH_PRINT_PRINTING) and [Printing](help:IDH_PRINT_GENERAL).

Legacy `.f00` bitmap font files may be specified instead of a font family, including for the Print role. Relative font paths resolve from the application settings directory; absolute paths are accepted. Print keeps its physical point size. The portable decoder supports recovered bitmap tables with bounded loading and safe failure behavior; source font files are not modified, installed globally, or bundled as a side effect. Native private faces preserve licensing/embedding metadata and do not become invented persistent font names. See [File Types](help:IDH_FILE_TYPES).

Vertical output has specific font consequences. TrueType fonts with usable vertical alternates can apply them to Japanese glyphs and punctuation; Latin remains upright. Raster fonts use the recovered punctuation exceptions and ink-position rules. If a suitable vertical treatment is unavailable, the application retains the defined native fallback rather than claiming identical legacy raster placement. This is the physical-paper clockwise-turn convention, not a new vertical document editing model. See [Margins, Vertical Printing, and Paper Orientation](help:IDH_PRINT_MARGINS).

Options > Printing also controls the Date/Time and AM/PM patterns, header offsets, ColorKanji printing policy, and ASCII grid behavior. Color Kanji is included only under its active list-mode policy, with list colors taking precedence; transient editor highlights do not print. PDF text, rendering, pagination, ranges, and cancellation are the accepted verification workflow. Native spool errors remain reportable, but browser JWPqt has no PrintSupport, Print, Preview, or font-to-browser-print path.

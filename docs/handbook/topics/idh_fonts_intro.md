# Fonts Introduction

JWPqt 2.04 separates Japanese role fonts, a matched single-byte ASCII font, clipboard bitmap rendering, and the physical Print role. This preserves the useful legacy distinction between screen and print responsibilities without asserting identical Win32 raster placement. Native documents also retain original byte/JIS identity as display-only metadata where applicable: code-page bytes use the ASCII face and remain upright, while JIS characters use Japanese font rules. Unrestricted Unicode has no invented byte identity.

Japanese System, Edit, List, KanjiBar, File, Big, Table, Bitmap, and Print roles can inherit from parent roles. A missing family inherits its parent family and size, while JWPqt preserves the requested name and reports fallback diagnostics. System/Edit/List/KanjiBar/File/Big/Table and Bitmap are application content roles, not desktop menu fonts. Big fits its pane on resize; Table remains 16 logical pixels; Print has an independent physical size. The Character Table is intentionally fixed at 16 logical pixels even when other display roles change.

The ASCII role is a separate single-byte font matched to the Japanese role height. Its private character-restricted face prevents a CJK-capable ASCII family from replacing Japanese glyphs. Legacy ASCII size/automatic values survive in settings for compatibility but do not alter matched height. Copy images and printing share that selection; optional Latin ligatures are disabled to preserve individual-character rendering and reliable PDF text extraction. No selected system face is installed globally, bundled, or relicensed by JWPqt; its original license and embedding restrictions remain relevant.

Legacy `.f00` Japanese bitmap files remain supported as explicit font entries. The portable decoder handles packed and holey JIS tables and byte- or word-aligned rows, producing private in-memory pixel-outline faces. It uses the original height for screen roles, fits Big to its pane, fixes Table at 16 px, and keeps Print in physical points. This is a native renderer implementation, not an emulated Win32 font layer. Source files are never changed, installed globally, or bundled by that selection, and their licensing applies.

TrueType/OpenType font shaping remains native. Vertical output follows the historical paper convention: Japanese glyphs are counter-rotated for reading after a clockwise turn, while Latin remains on the horizontal baseline. Fonts with a `vert` GSUB feature can supply vertical substitutions; missing features use the native fallback and malformed selected data fails explicitly.

# What you can Search for

Enter one language form in the Dictionary query field. Japanese input performs Japanese-to-definition lookup; ASCII input searches definitions. Do not mix Japanese and ASCII search text as if it were a single ordinary query. The input-mode buttons are editing aids, not a conversion promise: the query is interpreted from its completed text. Full-width/JASCII punctuation or letters can be normalized to ASCII when **JASCII to ASCII** is enabled; turn that option off only when the literal full-width form is required.

Direct lookup retains the legacy practical lower bounds: three ASCII characters, two kana characters, or one kanji. Hiragana and katakana are treated equivalently for ordinary Japanese lookup. Kana indexing has a legacy boundary consequence: kana searches behave as though Begin With is selected. A kanji-and-kana string must match a real indexed spelling; a visually plausible but unusual partial mixture can fail even though a full kanji or full kana spelling succeeds. See [Limiting the Search](help:IDH_DICT_LIMITS).

For English verb senses, use the conventional `to ` prefix when it is part of the definition you need, for example `to swim`; that distinguishes verb-style senses from a broad noun or related-word search. The source tags and slash-separated definitions remain data, so search results can vary with the configured dictionaries and their order.

Pattern searching is a separate direct-search feature, not Advanced search. Ordinary wildcard patterns require at least one kanji anchor; a trailing `*` also provides the legacy kana-prefix shortcut, but an anchorless `*` is invalid. Patterns may include kana plus `*` for zero or more characters, `?` for one character, `#` for one kanji, `[` for a beginning-of-word boundary, and `]` for an end-of-word boundary. ASCII or JASCII forms of the pattern characters are accepted where normalization permits them. `[` and `]` correspond to the Begin With and End With limits. Pattern work is bounded; it does not activate contingent retry. For inflected forms and uncertain word segmentation, use [Advanced Dictionary Searches](help:IDH_DICT_ADVANCED) instead.

Four full-width question marks, including the recognized spaced version form, are treated as a resource version query rather than wildcard syntax. A special legacy `!ID`-style query is not a general dictionary feature to rely on in the native interface. Inspect configured resources through **Tools > Manage Dictionaries** and Runtime Resources instead. That route reports the selected file and bounded validation result without inventing a version identifier.

Searches are explicit, not search-as-you-type. `Shift+Search` can force a one-request contingent retry without changing its saved setting, but it still observes ASCII, pattern, boundary, and work-limit gates. Clipboard lookup is also explicit through **From Clipboard**; see [Dictionary Options](help:IDH_DICT_OPTIONS). Recalled history text never initiates a search; see [Dictionary Introduction](help:IDH_DICT_GENERAL).

# The Page Layout Dialog Box

Page Layout controls the native document's print-oriented layout metadata. It provides the current document's margins, orientation, vertical setting, headers/footers, document summary, and related layout behavior. It is separate from the live scrolling editor: Print and Preview paginate a frozen snapshot in physical points, while Page Layout configures the data that snapshot uses. Existing JWP documents retain their saved layout. Text formats do not carry all native layout fields, so Save As/export can require loss confirmation. See [What is saved with a JWPce File?](help:IDH_FILE_CONTENTS) and [Printing](help:IDH_PRINT_GENERAL).

Default Page settings provide margins and orientation for new Japanese documents and newly imported text. Page Layout > From Default copies those defaults into the current document. Set as Default stages the current document's margins and orientation as future defaults. Cancel discards both staged changes. Accepting a page change is undoable in the document, but Undo does not roll back the application preference change. Headers, summary fields, and body content are not copied into defaults. See [Margins, Vertical Printing, and Paper Orientation](help:IDH_PRINT_MARGINS) and [Document Summary](help:IDH_PRINT_SUMMARY).

The dialog completes pending kana before it validates and applies metadata. Its title, subject, author, keyword, comment, header, and footer fields use the same Japanese input controls and Insert/Overwrite policy as document editing. Header/footer locations and date/time patterns are application printing options with explicit global scope, while the document's summary/header/footer data is native document metadata. See [Headers and Footers (Page Numbering)](help:IDH_PRINT_HEADERS), [Date and Time](help:IDH_PRINT_DATETIME), and [Advanced Layout Options](help:IDH_PRINT_ADVANCED).

Page Layout changes are native desktop functionality. The browser build has no PrintSupport and no Print/Preview commands, and it cannot open or save JPR referenced-file workspaces. Browser uploads still follow bounded format detection and downloads preserve the selected encoded bytes, but browser storage is not evidence of a printable desktop page-layout workflow.

# Creating a New File

File > New Japanese Document creates a new native JWP document. It starts with Japanese editing, conversion, formatting, and lookup insertion available, and it defaults to the Normal JWPce `.jce` choice when first saved. The document has its own tab, text, selection, cursor, formatting, and undo history; creating it does not replace the other documents already open. Until it receives a name through Save or Save As, it is an unnamed buffer and is not eligible for named-session restoration. See [Saving Files](help:IDH_FILE_SAVE) and [Changing the Current File](help:IDH_FILE_CHANGE).

File > New Plain-Text Document creates a UTF-8 text document. Japanese input and WNN conversion remain available, but native JWP paragraph formatting is deliberately not introduced into a plain-text saved format. Both kinds of new document can be edited in Japanese while their file representation remains distinct. If unrestricted Unicode outside the JWP repertoire is required, use the Japanese Editing mode control as documented by the editor; changing editing engine does not itself change a text document's encoding or format. See [File Types](help:IDH_FILE_TYPES) and [Japanese Encoding Systems](help:IDH_FILE_ENCODING).

The default-page settings initialize margins and orientation for fresh Japanese documents and newly imported text. Existing JWP files retain their own saved layout instead. Page Layout can copy application defaults into the current document, and it can stage the current document's margins/orientation as defaults for later documents. Headers, summary fields, and body text are not copied into the defaults. This means a new document has predictable page defaults without inheriting another document's header or summary content. See [The Page Layout Dialog Box](help:IDH_PRINT_LAYOUT) and [Margins, Vertical Printing, and Paper Orientation](help:IDH_PRINT_MARGINS).

When closing the last tab, JWPqt normally asks whether to exit. Choosing No leaves a clean unnamed Japanese document, but it does not recover edits discarded during the preceding close. The confirmation can be changed in settings. On the Web build, new browser working copies still follow the editor's format rules, but saving creates a download rather than a persistent desktop pathname.

# Display Options

Display Options configures the interface around documents without modifying their text, selections, formats, or Undo history. Toolbar, status-bar, candidate-bar, scrollbar policy, and candidate-bar position are persistent preferences. The toolbar is visible by default; narrow windows expose remaining actions through its extension button. Use [Toolbar Customization](help:IDH_OPTIONS_TOOLBAR) for its commands, docking, and presentation rather than treating visibility as the entire toolbar configuration.

Status bar, candidate bar, vertical and horizontal document scrollbars, and the candidate-bar scrollbar are on by default; the candidate bar is below the document by default. The default color-scheme preference is System. Autoscroll is on by default, and its repeat delay is 100 ms with an accepted range of 0 through 10,000 ms.

The Color scheme control offers **System**, **Light**, and **Dark**. System follows Qt's platform color scheme on desktop systems. In the WebAssembly build it follows the browser `prefers-color-scheme` setting and changes live when that setting changes. Light and Dark are persistent overrides and ignore later system changes until System is selected again. Recoloring updates the interface and vector artwork but does not edit a document, accept an active conversion, or alter Undo.

Selection autoscroll starts enabled with the original 100 ms repeat delay. While extending a mouse selection within one-third of a text line from a top or bottom edge, the document moves one line immediately and continues at the configured delay. Disable it to keep edge dragging in the current view. A zero delay uses Qt's shortest event-loop interval. The policy applies to existing and new documents without changing their text, selection, scroll position, or history.

The Colors page stages information-heading, kanji-list, and uncommon-kanji colors, list mode, and uncommon-character coloring. Enter `#RRGGBB`, choose a color, or select Inherit. Explicit imported values take precedence over absent source overrides; Inherit returns authority to the existing native INI color policy. Information headings adapt when needed for theme contrast. Special Windows palette references are preserved and disclosed rather than misread as RGB. Unsupported heading/list references remain visible as such, while uncommon color uses the source green fallback.

Default Settings supplies red information headings (`#FF0000`), blue kanji-list text (`#0000FF`), gray uncommon-kanji text (`#585858`), list coloring Off, uncommon coloring Off, and uncommon-character marks off. The color-mode source values are Off, Color listed kanji, or Color unlisted kanji; retained source modes above 2 remain selectable and disclosed.

Color Kanji policies update display decoration, not document content. List membership can color the appropriate kanji; uncommon-character marks are small dots in conversion and lookup bars and never become copied or inserted text. Changing a color or theme does not rerun a lookup, replace results, or change selected, copied, or inserted text. Font roles are separate from desktop menu fonts; configure them in [Font/Format Options](help:IDH_OPTIONS_FONT) and [Fonts Introduction](help:IDH_FONTS_INTRO).

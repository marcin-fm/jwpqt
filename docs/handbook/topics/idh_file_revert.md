# Opening the Same File Again

File > Revert reloads the current document from its current source. Use it to abandon all in-memory changes since the saved baseline or to deliberately reread a file changed outside JWPqt. Revert is strict: it does not invoke interactive damaged-JWP recovery. This rule protects the meaning of “reload” by ensuring that a source reload cannot quietly turn into a partial recovery. If the file is damaged or invalid under its stored/selected representation, report and resolve that error instead of assuming that a readable prefix is an acceptable replacement. See [Common Difficulties Opening Files](help:IDH_FILE_PROBLEMS) and [Opening an Existing File](help:IDH_FILE_OPEN).

When a pathname is already open and another Open request names it, the duplicate-file policy may offer reload, activate the existing tab, or create an independent copy. Revert is the direct command for the reload case. Activating leaves the current in-memory state untouched. An independent copy has separate edits and is not synchronized, so it is not a substitute for Revert when the intent is to update one tab from disk. See [Duplicate Files](help:IDH_FILE_DUPLICATE) and [Changing the Current File](help:IDH_FILE_CHANGE).

Revert works with the document's known file format rather than needlessly guessing again. This is particularly important for text choices that are intrinsically ambiguous without a BOM or explicit encoding. Recent files retain their text encoding or JWP code-page information for the same reason. A JFC document follows its JFC policy; a native JWP document validates as a structured document. Revert is not a conversion command, and it does not change the document's encoding merely because another possible decoding could render some bytes. See [Japanese Encoding Systems](help:IDH_FILE_ENCODING) and [JFC Files](help:IDH_FILE_JFC).

If unsaved work must be preserved before reverting, Save it under its current name, use Save As for another working identity, or use Export Copy for a derivative that leaves the live baseline and history unchanged. Do not depend on session restoration to preserve unnamed or unsaved text: named-session archives store only named references after save/discard checks. See [Saving Files](help:IDH_FILE_SAVE) and [Working with Projects](help:IDH_FILE_PROJECT).

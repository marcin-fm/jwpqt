# Choosing an ASCII Font

Choose the ASCII and legacy extensions role in **Tools > Options > Fonts** when you need a distinct single-byte face for legacy code-page bytes. JWPqt matches that face to the Japanese role's rendered height rather than presenting an independent ASCII point or pixel size. This retains the legacy intent that ASCII and Japanese text line up while avoiding an obsolete sizing mechanism. Stored `ASCII.Size` and `ASCII.Auto` entries remain preserved for source compatibility but do not override the matched height.

The ASCII selector always exposes the complete public system family list. It is separate from the Japanese and printer lists, which normally filter to families advertising Japanese support. If the selected face is missing, JWPqt retains the original family name and uses native fallback with a diagnostic. The role is private and character-restricted: a selected ASCII family that also contains CJK glyphs cannot silently become the Japanese display face. This guards the distinction between legacy byte identity and Japanese JIS rendering.

Native JWP documents preserve the original byte/JIS distinction as display-only metadata even where both forms map to the same Unicode character. Raw code-page bytes use the ASCII face and remain upright; JIS characters use the Japanese face and its vertical rules. Clipboard images, PDF bodies, and headers preserve that display identity without changing text, document tokens, or Undo. Switching a document to unrestricted Unicode intentionally removes that native display metadata rather than inventing a byte identity.

The selection also applies to printing and copied bitmap images. Optional Latin ligatures are disabled so individual source-style characters and PDF text remain reliable. This does not modify the font installed on the host, bundle it into JWPqt, or change its license or embedding restrictions. If a private font face cannot be used, the original selection is still recorded and the fallback is visible through diagnostics.

The legacy manual required a TrueType ASCII font except on Windows CE machines lacking TrueType support. JWPqt's native policy is instead role-based and platform-independent: select an available public system family, let it match Japanese height, and rely on fallback diagnostics when unavailable. See [Fonts Introduction](help:IDH_FONTS_INTRO), [Font/Format Options](help:IDH_OPTIONS_FONT), and [Choosing a Japanese Printer Font](help:IDH_FONTS_PRINTER).

# Header and Footer Example

To build a repeatable native page identity, enter fixed wording and substitutions into the document's header/footer fields. For example, use `&L` in a header field to print the current document Title, `&D` in a footer field to print the configured date, and `&P` where a page number is required. A field may combine literal text with multiple codes, such as `Draft: &L` or `&N - &P`. To place a literal ampersand in such text, use `&&`. The complete code set is documented in [The Header and Footer Strings](help:IDH_PRINT_HEADSTRINGS).

The Title value is set in the document summary, not inferred from the filename. Subject, Author, Keywords, and Comment can similarly be inserted through `&S`, `&A`, `&K`, and `&C`; `&F` supplies the full filename and `&N` supplies its base name. Date/time substitutions use the patterns configured in Options > Printing and the one timestamp captured for the output job. Unknown ampersand sequences remain literal, so inspect preview instead of expecting an unrecognized code to produce a guessed value. See [Document Summary](help:IDH_PRINT_SUMMARY) and [Date and Time](help:IDH_PRINT_DATETIME).

Choose the relevant header/footer field in Page Layout. JWP supports separate odd/even header/footer fields and optional first-page suppression, so double-sided layouts can use different content per side. The printed field must fit within valid paper geometry. Header/footer positions are adjusted through the advanced line/character offsets, and Preview shows the same snapshot that Print uses. See [Headers and Footers (Page Numbering)](help:IDH_PRINT_HEADERS) and [Advanced Layout Options](help:IDH_PRINT_ADVANCED).

This example is native desktop output behavior, including PDF. PDF/preview text, pagination, rendering, ranges, and cancellation are the project acceptance path; physical printer hardware is not required. WebAssembly provides no JWPqt Print or Preview command, so an example header/footer layout cannot be emitted by the browser port.

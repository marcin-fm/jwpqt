# Backup Files

JWPqt can keep the immediately previous disk version when saving. The setting is **Keep the previous disk version** and is off by default. When enabled, it appends `_BAK` to the complete destination filename. For example, saving `notes.txt` preserves the prior disk bytes as `notes.txt_BAK`; a native document is treated the same way. The backup preserves the old file's exact bytes and encoding, rather than re-encoding it through the current document. See [Saving Files](help:IDH_FILE_SAVE).

The policy applies to Save, Save As, and Export Copy when they overwrite an existing destination. New targets leave any pre-existing backup alone. Before publishing the new document, the application copies the old destination to the backup name. An invalid output encoding or failed backup creation does not replace the document and leaves the old backup intact. Backup paths that are open documents, protected application data, or symlinks are rejected. Ordinary permissions are retained, but this is not a promise to preserve every filesystem-specific attribute. See [Temporary Files and System Failures](help:IDH_FILE_TEMP) and [Duplicate Files](help:IDH_FILE_DUPLICATE).

This feature is deliberately not described as a two-file transaction. If creation of the backup succeeds but publication of the new document subsequently fails, the backup contains the still-current disk version. That result is useful recovery evidence, but it does not make the requested new save successful. Check the reported error and the existing document before retrying. Atomic publication protects the destination against partial replacement; the backup protects the immediately preceding bytes when the option is enabled. See [Common Difficulties Opening Files](help:IDH_FILE_PROBLEMS).

The legacy documentation described backups as a normal default, but the 2.04 native setting defaults off. Enable it deliberately when preserving the previous on-disk version is required. It is separate from session restoration, which saves named-file references rather than document content, and separate from projects, which save workspace references/settings rather than unsaved text.

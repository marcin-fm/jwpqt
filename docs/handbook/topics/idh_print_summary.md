# Document Summary

The JWP document summary stores five native metadata fields: Title, Subject, Author, Keywords, and Comment. They are associated with the document rather than derived automatically from its filename. Page Layout provides the editing boundary for this metadata, using the same Japanese input controls and Insert/Overwrite policy as document editing. Pending kana is completed before validation and acceptance. See [The Page Layout Dialog Box](help:IDH_PRINT_LAYOUT).

Summary values can be printed through headers and footers. The substitution codes are `&L` for Title, `&S` for Subject, `&A` for Author, `&K` for Keywords, and `&C` for Comment. This permits a header/footer design that remains current when summary text changes, without manually revising every field. The output job freezes summary metadata before Print or Preview dialogs open, so subsequent metadata changes do not alter that job. See [The Header and Footer Strings](help:IDH_PRINT_HEADSTRINGS) and [Actually Printing Something](help:IDH_PRINT_PRINTING).

The summary is native JWP metadata, alongside paragraph/page layout, hard page breaks, and headers/footers. Normal JWPce (`.jce`) and JWP (`.jwp`) preserve this structured content through their common native codec. Text formats cannot generally represent it, and Save As or Export Copy asks for the appropriate loss confirmation rather than silently pretending the data survived. Export Copy is useful when a text derivative is needed but the active native document and its summary must remain unchanged. See [What is saved with a JWPce File?](help:IDH_FILE_CONTENTS) and [Saving Files](help:IDH_FILE_SAVE).

Default Page settings do not copy the current document's summary, header/footer fields, or body into new documents. They only stage page margins and orientation for future documents. Projects preserve supported settings and file references/format metadata, not unsaved document text or undo history; save a document before depending on its summary in a workspace. WebAssembly persists browser-owned working copies/settings, but it cannot use JWPqt's native Print/Preview workflow, so summary-to-header output is unavailable there.

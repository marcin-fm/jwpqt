# Choosing a Japanese Printer Font

The Print role is configured in **Tools > Options > Fonts** and is separate from screen-role sizes. Its dialog size is physical points, stored on disk in tenths of a point. Automatic Print uses the document font family; an explicit family uses Qt's native fallback. The setting persists through normal configuration and projects. An invalid explicit print font is rejected before any output is written, rather than allowing a partial or silently substituted print job.

Screen roles use logical pixels because they serve the current display. Print points describe physical output and interact with page orientation, margins, and the printer-width view mode. Changing a screen display font does not claim to change printed scale. Conversely, printer-width formatting follows the configured physical Print font and current Page Layout while leaving document text, metadata, saved state, and Undo unchanged.

An explicit legacy `.f00` file can be selected for Print just as for other Japanese roles. Relative paths resolve from the settings directory and absolute paths are accepted. The native decoder creates a private pixel-outline face; Print retains its physical point size even though screen roles use the bitmap's original height. The source file is never altered, installed globally, or bundled merely through selection, and its original license remains applicable. Private generated faces have bounded memory and embedding restrictions. Print kanji-list coloring defaults off and requires active list coloring.

Vertical output retains the recovered paper convention instead of offering a generic top-to-bottom layout. Japanese glyphs are counter-rotated for reading after a clockwise quarter turn. Latin and recovered exception punctuation remain on the horizontal baseline. TrueType/OpenType fonts with a `vert` GSUB feature use its available vertical substitution behavior; a missing feature uses the native fallback, and malformed data fails explicitly. This is not a promise of pixel-identical legacy Win32 raster placement.

JWPqt's accepted printing verification is native PDF text, pagination, rendering, ranges, cancellation, and atomic replacement. Physical-printer hardware is not an acceptance gate, and no claim is made for every printer backend. ColorKanji_Printing applies kanji colors only when list coloring is active, including headers and footers; later preference changes do not alter a captured print job. See [Font/Format Options](help:IDH_OPTIONS_FONT), [Fonts Introduction](help:IDH_FONTS_INTRO), and [Support](help:IDH_SUPPORT_GENERAL).

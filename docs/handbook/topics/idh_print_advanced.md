# Advanced Layout Options

Advanced printing options govern header/footer placement and native JWP ASCII grid behavior. Header and footer distances are measured in lines, in hundredths, from 0 to 10. Left and right header extensions are measured in characters. These positions determine how header/footer content sits relative to the page body and margins; Preview uses the same settings as Print. Offsets that put text outside the paper, or other invalid geometry, fail safely before an existing PDF is replaced. See [Headers and Footers (Page Numbering)](help:IDH_PRINT_HEADERS) and [Actually Printing Something](help:IDH_PRINT_PRINTING).

The ASCII grid control defaults on. For native JWP documents it distributes next-cell padding before tabs and on eligible wrapped lines, supporting the source-style fixed Japanese cell layout. It does not pad final paragraph ends or ASCII immediately followed by JIS text. Japanese characters remain fixed cells and tabs advance one cell even when ASCII padding is off. This behavior is applied by the print renderer, not treated as a global transformation of document text. Unrestricted Unicode documents retain ordinary Qt layout. See [Page Breaks and Formatting](help:IDH_PRINT_PAGEBREAK).

Advanced layout also interacts with margins and orientation. The renderer paginates in physical points, preserving native paragraph indents, spacing, hanging indents, and hard page breaks. It may allow one eligible closing punctuation or small-kana cell into the physical right margin under the configured relaxation rule. Printer Setup applies accepted margins/orientation as an undoable change only to its original document. See [Margins, Vertical Printing, and Paper Orientation](help:IDH_PRINT_MARGINS).

These are application print options captured with each job. They do not cause the editor screen to become a full paper-layout display, and later changes cannot rewrite an already frozen preview/print job. Native PDF preview verifies the resulting page geometry and text. WebAssembly excludes Print and Preview because it has no Qt PrintSupport; therefore advanced layout values do not create browser printable pages in JWPqt.

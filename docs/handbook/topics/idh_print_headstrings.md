# The Header and Footer Strings

Headers and footers accept ordinary text plus case-insensitive substitutions that are evaluated during native printing or preview. `&A` inserts Author, `&C` Comment, `&D` the configured date pattern, `&F` the full file name, `&K` Keywords, `&L` Title, `&N` the base filename, `&S` Subject, `&T` the configured time pattern, and `&P` the page number. `&&` inserts a literal ampersand. Unknown codes remain literal text, rather than being silently transformed. See [Headers and Footers (Page Numbering)](help:IDH_PRINT_HEADERS).

The summary fields provide the author/comment/keyword/title/subject values. Date and time come from Options > Printing patterns and a timestamp captured for the job. This makes page output coherent: a long print run does not obtain a different timestamp partway through. The print/preview snapshot also freezes the document text, metadata, font, and selection before dialogs open, so later header edits cannot alter the already prepared job. See [Document Summary](help:IDH_PRINT_SUMMARY), [Date and Time](help:IDH_PRINT_DATETIME), and [Actually Printing Something](help:IDH_PRINT_PRINTING).

Header and footer strings use the native Japanese input controls with the same Insert/Overwrite policy as the document. Complete pending kana before acceptance is automatic at the Page Layout boundary. Separate odd/even fields and first-page suppression are available for JWP documents. Offsets and available paper geometry must still allow the rendered strings to fit; invalid output geometry fails before a prior PDF is replaced. See [Advanced Layout Options](help:IDH_PRINT_ADVANCED).

These substitutions belong to native JWP page-layout metadata. Text formats cannot necessarily retain headers/footers, and the port asks before loss during relevant text output. On WebAssembly, JWPqt's Print and Preview commands are unavailable because there is no Qt PrintSupport. Browser upload/download and IndexedDB working copies do not implement a browser header/footer output path.

# The Exit Command

File > Exit, explicit Quit, and an application-level close all leave the editor through workspace save checks. The command checks every modified document before discarding any one of them. For each changed file, choose Save, Discard, or Cancel. Cancel keeps the workspace available rather than producing a partly closed session. This behavior also applies to Close All. The window close button can be configured to close only the active document; Alt-close forces application exit, and Ctrl-close forces file close. See [Closing Files](help:IDH_FILE_CLOSE).

Saving during exit uses each document's own format and path. Save All visits every document, including unnamed files, and stops at the first cancellation or error. A failed encoding validation, filesystem failure, or cancelled Save As prevents that document from being treated as clean. Backup behavior, when enabled, is also a save operation with its own failure protection. See [Saving Files](help:IDH_FILE_SAVE) and [Backup Files](help:IDH_FILE_BACKUP).

The optional **Restore named files from the previous session** feature is independent of closing. On successful exit after the save/discard checks, it records currently open named-file references, saved formats, and active tab order in app-scoped `last-session.jpr`. It never records unnamed buffers or unsaved text. At the next startup, the archive is read before command-line files, with missing or invalid references reported while usable files continue opening. A corrupt, locked, or externally changed archive is not overwritten; if exit saving of it fails, choose Cancel or exit without updating it. Disabling restoration leaves an existing archive unchanged. See [Working with Projects](help:IDH_FILE_PROJECT).

On the Web build, closing concerns browser-owned staged copies and settings in IndexedDB. Clearing browser site data removes those copies. Browser JPR workspaces and printing remain unavailable, so exit/session behavior does not create a desktop-style referenced-files project.

# Working with Projects

JWPqt projects use current Unicode `.jpr` workspaces. File > Open Project can replace the currently open tabs or append the project's tabs. Files and supported settings are validated before replacement, and save/discard/cancel choices are collected before an editor is removed. Append retains already-open buffers and their known formats rather than replacing them with stale disk copies. An unreadable reference is reported without making a usable workspace silently disappear. See [Opening an Existing File](help:IDH_FILE_OPEN) and [Closing Files](help:IDH_FILE_CLOSE).

Save Project stores file references, supported settings, explicit formats/code pages, and native tab metadata/order. It does not store unsaved text or undo history. Save documents first, or deliberately save references only; nonempty unnamed documents must be saved before they can become references and cannot silently vanish from a workspace. A reference-only save does not accept an active conversion. Projects retain unsupported imported settings visibly and require approval when opening rather than silently pretending those settings are implemented. See [Saving Files](help:IDH_FILE_SAVE) and [File Types](help:IDH_FILE_TYPES).

Legacy Windows paths require explicit equivalent Linux directory mappings. The process working directory is not changed. Ambiguous legacy project text asks for its encoding rather than assuming UTF-8. A current native project can be opened at startup as `jwpqt workspace.jpr`; an encoding fallback can be supplied for ambiguous legacy references, while explicit native metadata takes priority. Recent project entries reopen as projects. Project restoration is bounded and rejects nested projects, rather than recursively treating arbitrary references as more workspaces. See [Common Difficulties Opening Files](help:IDH_FILE_PROBLEMS).

Named-session restoration is related but distinct. The opt-in `last-session.jpr` archive records named files and tab order after exit checks, before later command-line activation, but it is not the current project and is not added to project history. Browser JPR Open and Save are unavailable because browser uploads cannot provide stable access to every referenced local file. Browser storage may persist working copies and preferences in IndexedDB, but it is not a JPR workspace.

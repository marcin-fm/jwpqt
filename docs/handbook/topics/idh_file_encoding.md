# Japanese Encoding Systems

JWPqt uses Unicode in its interface while retaining explicit legacy format boundaries for Japanese documents and text codecs. The supported text choices are UTF-8, UTF-7, UTF-16LE, UTF-16BE, EUC-JP, Shift-JIS, New-JIS, Old-JIS, and NEC-JIS. The native JWP/JCE codec is separate: it preserves the structured Japanese document model, including paragraphs and page breaks, rather than treating a JWP file as ordinary encoded text. JFC is another separate policy: it is plain text, opened as UTF-8 first with strict legacy-EUC fallback and saved as UTF-8 without a BOM. See [File Types](help:IDH_FILE_TYPES) and [JFC Files](help:IDH_FILE_JFC).

UTF-8 and UTF-7 are available as explicit text formats. UTF-7 detection deliberately does not pretend that a shared ASCII-looking payload is uniquely identifiable; choose UTF-7 explicitly when necessary. UTF-16 preserves its byte order and an input BOM. BOM-marked UTF-16 is detected, but an unmarked UTF-16 file must be opened through its explicit filter or encoding choice. When changed to UTF-16 through the encoding controls, JWPqt writes a BOM to make later detection possible. Supplementary Unicode characters are supported in UTF-16, while malformed surrogate pairs are rejected. See [Opening an Existing File](help:IDH_FILE_OPEN).

EUC-JP and Shift-JIS use strict recovered JIS X 0208 mappings. Their generic codecs reject malformed bytes, unassigned cells, vendor extensions, JIS X 0212, and halfwidth kana rather than silently substituting text. New-, Old-, and NEC-JIS are distinct escape-sequence text formats and should be selected according to the source file's known encoding. Where bytes are ambiguous, do not assume a plausible display proves the encoding: select the intended codec and reopen. Save As validates that the current content can be represented before publishing a target, so a failed conversion does not partially replace it. See [Saving Files](help:IDH_FILE_SAVE) and [Common Difficulties Opening Files](help:IDH_FILE_PROBLEMS).

Text import can still use Japanese editing when all content is representable in JWP, but it retains its text-file encoding and format. To keep unrestricted Unicode outside the JWP repertoire, turn off Japanese Editing; that changes the editing engine, not the saved text format. The Web port uses the same bounded detection after upload, but browser upload/download replaces native path ownership.
